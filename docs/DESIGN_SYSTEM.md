# CreativeReporter 디자인 시스템

이 문서는 **규칙**이다. 새 UI를 만들거나 기존 UI를 고칠 때 여기 없는 값을 새로 만들지 않는다.

## 왜 규칙이 필요한가 — 현황 실측 (2026-07, index.html)

| 축 | 실측 | 문제 |
|---|--:|---|
| 색상 | 하드코딩 **112종** + 변수 36개 | 같은 회색이 5가지 값으로 존재. 역할이 아니라 그때그때의 감으로 골라짐 |
| 글자 크기 | **22종** (6.5px~34px, 0.5px 단위까지) | 위계가 아니라 연속체. 11px과 11.5px은 아무도 구분 못 한다 |
| 글자 굵기 | **8종** (500·600·650·680·700·740·750·800) | 650과 680의 차이는 화면에서 보이지 않는다 |
| 모서리 | **15종** (2~18px, 999) | 카드·칩·버튼이 제각각 |
| 간격(gap) | **19종** (1~26px) | 배수 관계가 없음 |
| 안쪽 여백 | **128종** | 사실상 무규칙 |

이 산포가 "난잡한 느낌"의 정체다. 각 값이 개별적으로는 합리적이었지만, 합쳐지면 **위계가 읽히지 않는다**.

---

## 1. 색 — 역할이 먼저, 색은 나중

색은 네 가지 역할군에만 속한다. **다섯 번째 역할군을 만들지 않는다.**

### ① 지면 (Surface) — 깊이 4단계
| 토큰 | 역할 |
|---|---|
| `--canvas` | 페이지 바닥. 콘텐츠가 놓이는 배경 |
| `--surface` | 콘텐츠 면 (본문·표) |
| `--surface-2` | 한 단계 들어간 면 (표 헤더·입력·비활성 칩) |
| `--surface-3` | 구분선·가장 옅은 채움 |

규칙: **깊이는 4단계까지.** 다섯 번째 회색이 필요하면 그건 레이아웃 문제지 색 문제가 아니다.

### ② 글자 (Text) — 위계 3단계
| 토큰 | 역할 |
|---|---|
| `--ink` | 값·이름 등 **읽어야 하는 것** |
| `--muted` | 라벨·설명 등 **맥락** |
| `--faint` | 단위·보조 등 **있는 줄만 알면 되는 것** |

규칙: **3단계뿐.** 네 번째 회색 글자를 만들지 말고 위 셋 중 하나로 결정한다.

### ③ 브랜드 (Brand) — `--karrot`
**네비게이션과 활성 상태에만.** 데이터 영역(숫자·점수·차트)에는 절대 쓰지 않는다.
주황이 데이터에 섞이는 순간 "이게 성과가 좋다는 뜻인가?"라는 오독이 생긴다.

### ④ 성과 (Semantic) — 5단계, 데이터 전용
`--g2`(매우 좋음) → `--g1`(좋음) → `--mid`(보통) → `--w1`(나쁨) → `--w2`(매우 나쁨), 각 `-f` 채움색 쌍.

규칙: **성과 판정에만.** 장식·구분·강조에 쓰지 않는다. 반대로 성과 판정은 이 5단계 외의 색을 쓰지 않는다.
(점수 10단계 `.sd0~.sd9`는 이 축의 세분판으로, 같은 순서 위계를 지킨다.)

> **한 줄 규칙**: 데이터에 브랜드색 금지, 브랜드 영역에 성과색 금지.

## 2. 타이포 — 역할 6개, 굵기 3개

| 토큰 | 크기 | 역할 |
|---|--:|---|
| `--fs-display` | 26px | 페이지 대표 숫자 하나 |
| `--fs-title` | 17px | 섹션 제목 |
| `--fs-body` | 13px | 본문·표 값 |
| `--fs-data` | 13px | 숫자 (반드시 `tabular-nums`) |
| `--fs-label` | 11.5px | 라벨·칩 |
| `--fs-micro` | 10.5px | 단위·각주 |

| 토큰 | 값 | 역할 |
|---|--:|---|
| `--w-reg` | 500 | 본문 |
| `--w-med` | 650 | 라벨·강조 |
| `--w-bold` | 780 | 숫자·제목 |

규칙: **크기 6개·굵기 3개.** 그 사이 값(12px, 680 등)을 새로 만들지 않는다.
숫자는 예외 없이 `font-variant-numeric: tabular-nums` — 자릿수가 흔들리면 표를 세로로 훑을 수 없다.

---

## 3. 간격 — 4px 배수

`--sp-1:2 · --sp-2:4 · --sp-3:6 · --sp-4:8 · --sp-5:12 · --sp-6:16 · --sp-7:20 · --sp-8:24`

규칙: 여백은 이 8개 중에서만 고른다. 5px·7px·9px·11px·13px·14px을 새로 만들지 않는다.

## 4. 모서리 — 4개

`--rad-chip:3 · --rad-ctl:7 · --rad-card:11 · --rad-pill:999`

규칙: 칩은 chip, 버튼·입력은 ctl, 카드·패널은 card, 알약형만 pill. 그 사이 값 금지.

## 5. 선과 그림자

- 구분선은 `--line` **1종**(=`--surface-3`). 굵기 1px. 점선은 '도움말 있음' 표시 전용.
- 그림자는 `--sh` **1종**. 떠 있는 것(모달·팝오버)만 사용. 표·카드는 그림자 대신 지면 단계로 구분한다.

## 6. 밀도

표는 이 도구의 본체다. 행 높이는 테마가 정하고, 개별 화면이 임의로 바꾸지 않는다.

---

## 7. 테마 — 규칙은 공유, 성격만 다르게

테마는 **색 역할값과 밀도·모서리만** 바꾼다. 구조·정보 위계·성과 5단계의 의미는 어느 테마에서도 같다.
기기 단위 설정(`localStorage.cr_theme`)이며 데이터·점수에 영향이 없다.

| 테마 | 성격 | 언제 |
|---|---|---|
| **당근** (기본) | SEED 계열 중성 회색 + 브랜드 오렌지를 활성 지점에만 | 평소. 당근 제품군과 같은 결 |
| **정밀** | 저채도 중성 회색, 행 높이 6px, 각진 칩, 얇은 구분선 | 표를 오래 들여다보며 분석할 때 (한 화면에 더 많은 행) |
| **차분** | 따뜻한 종이, 행 높이 13px, 알약 칩, 큰 이름 | 훑어보기·공유·발표 |
| **야간** | 어두운 지면에서 숫자가 떠오름 | 장시간 분석, 어두운 환경 |

### 테마를 추가할 때
1. `:root[data-theme="이름"]`에 **색 역할 토큰만** 정의 (지면 4·글자 3·브랜드·성과 5쌍)
2. 성격이 필요하면 밀도·모서리 규칙을 **4곳까지만** 덮는다: 표 행 · 칩 · 점수 배지 · 카드 라운드
3. 다크 계열이면 변수로 덮이지 않는 것(`.sd0~.sd9` 등)도 함께 보정
4. `THEMES` 배열에 등록

---

## 8. 글

- 라벨은 사용자가 아는 말로. 시스템 용어(payload, kv) 금지.
- 버튼은 눌렀을 때 일어나는 일을 그대로: "저장" → 토스트 "저장했어요".
- 빈 화면은 안내가 아니라 **다음 행동**을 제시한다.
- 오류는 사과하지 않고, 무엇이 잘못됐고 어떻게 고치는지 말한다.
- 해요체로 통일.

---

## 9. 수렴 전략

기존 코드의 값을 한 번에 전부 바꾸지 않는다. **새로 쓰거나 고치는 부분부터** 위 토큰을 쓰고, 손대는 김에 주변을 정리한다. 목표는 완벽한 일괄 교체가 아니라 **새 값이 더 이상 늘지 않는 것**이다.
