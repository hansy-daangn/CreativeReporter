[3] 검증 재설계 — 교차 잣대 원칙
════════════════════════════════════════════
"검증 지표는 장애 지점과 다른 원천에서 와야 한다."

기존 3-(a) 행수·비용합 대조는 유지하되, 아래를 **차단 조건**으로 승격해라(하나라도 걸리면 그 채널은 기록하지 않고 보류):
  P1. 몰로코 `노출 수` 합계 == `_afImp` 합계        → 폴백 발화. 콘솔 미적재로 판정
  P2. 몰로코 `SUM(노출 수)` == 0                     → 콘솔 미적재
  P3. 어떤 행이든 `클릭 수 > 노출 수`                → 물리적 불가
  P4. 콘솔 유래 키(`_v25`~`_v100`, `_m_installs`)가 그 주 전 행에서 전부 비어 있음 → 콘솔 미적재의 2차 지문
  P5. 직전 주 대비 노출 합계 90% 이상 급감
  P6. 필수 키(`비용`·`노출 수`·`클릭 수`, 몰로코·메타는 `어트리뷰션 수`) 보유율 < 99%

보류 시: 그 채널만 건너뛰고 나머지는 기록한다. Slack: `[CR] {채널} 보류 ⚠️ {M/D}주 — {P번호} {사유}. 다음 슬롯에서 재시도`

[4] NFC 정규화 의무화
════════════════════════════════════════════
소재명으로 조인·대조·백필하는 **모든 지점**에 정규화를 건다.
  BigQuery: NORMALIZE(Creative_Title, NFC)
  Postgres: normalize(ad_name, NFC)
문서에 "이름이 분명 있는데 0건 매치면 hex를 찍어 NFC/NFD·제로폭(U+200B)·NBSP를 의심하라"는 진단 절차를 남겨라.
(구글 ACE 행의 U+200B 규칙은 기존대로 유지 — 그건 의도된 마커다.)

[5] 적재 규약 — 기존 데이터에서 역추출된 것
════════════════════════════════════════════
- `0`은 '없음'이 아니다. 값을 못 받았으면 **키를 아예 넣지 마라**(절대 규칙 5, 기존 유지).
  근거: 기존 `_v25` 4,846행 중 값 0 = 0건, `_q_revD0`·`_q_retD1Base`도 0건. 반면 `_m_installs`는 347건이 0 → 이 키만 0 허용.
  신규 적재를 다른 규약으로 넣으면 주차 간 추이가 왜곡된다.
- 재적재는 **삭제 후 재삽입 금지, 제자리 UPDATE 또는 `payload = 신규키 || 기존payload` 병합**으로 하라.
  이유: `_m_resReal`(ffprobe 실측)·`_svc`·`_name` 등 **재현 불가능한 키**가 payload에 들어 있어 삭제하면 영구 손실된다.
  (BACKFILL_TASK.md의 delete-후-재적재 지시도 이 원칙에 맞게 고쳐라.)
- Supabase에는 거짓 0 차단 트리거 `cr_strip_false_zero_impressions`가 있다(클릭>0인데 노출=0이면 노출 키 제거).
  이건 마지막 방어선이지 1차 방어가 아니다 — 트리거가 걸렸다는 건 이미 [3]에서 잡았어야 한다는 뜻이다.
