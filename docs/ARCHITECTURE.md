# CreativeReporter 구조와 매커니즘

퍼포먼스 소재 성과분석 대시보드의 전체 설계 문서. 이 문서만 읽으면 시스템이 어떻게 동작하는지, 왜 그렇게 설계됐는지 알 수 있다.

## 1. 한눈에 보기

```
[Meta/Moloco/Google CSV]                [Google Ads 보고서들]
        │ 드래그&드롭                        │ (광고그룹 보고서·이름 매핑)
        ▼                                   ▼
┌──────────────────────────────────────────────────────┐
│  index.html (단일 파일, 바닐라 JS/CSS/SVG, 의존성 0)   │
│  파싱 → 매체 판별 → 필터 → 뷰 누적 → 채점 → 렌더        │
└──────────────┬───────────────────────────────────────┘
               │ RPC (비밀번호 게이트)
               ▼
┌──────────────────────────────────────────────────────┐
│  Supabase (Postgres)                                  │
│  sr_weekly_creative_stats  ← 주간 성과 원본 (JSONB)        │
│  sr_kv                  ← gmap·ginfo·ocr·ytt·nameovr·svcovr│
│  sr_users               ← 사용자 계정·승인 상태·권한       │
│  sr_user_marks          ← 즐겨찾기·내 소재 (계정 단위)     │
└──────────────────────────────────────────────────────┘

배포: GitHub Pages (main 머지 → Actions 자동 배포, 실패 시 백오프 재시도 3회)
관리: admin.html — 가입 신청 승인/거절 (관리자 비밀번호 게이트, 저장소와 별도 URL)
```

- **프론트엔드**: `index.html` 하나. 프레임워크·번들러·외부 라이브러리 없음. 모든 계산(집계·채점·차트)은 브라우저에서 수행.
- **백엔드**: Supabase Postgres. 클라이언트는 REST RPC만 호출. 테이블 직접 접근은 RLS로 전면 차단.
- **호스팅**: GitHub Pages. `main`에 머지하면 `.github/workflows/pages.yml`이 배포(일시 거부 대비 90초·5분 백오프 재시도).

## 2. 데이터 모델

### sr_weekly_creative_stats — 주간 성과 원본
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | bigint identity | PK |
| channel | text | `Meta` `Moloco` `Google` (그 외·'기타'는 서버가 거부) |
| week_start | date | 주 시작일(월요일) |
| ad_name | text | 소재 식별자 (구글은 소재 URL) |
| payload | jsonb | 그 주의 원본 수치 전부 |
| uploaded_by | text | 업로더 서명 (`/hansy` 입력 시 `hansy`, 기본 `unknown`) |
| uploaded_at | timestamptz | 자동 기록 |
| cost_krw·impressions·clicks·installs·active_users | numeric **generated** | payload에서 자동 파생(콘솔 조회용, 쓰기 불필요) |

- **UNIQUE(channel, week_start, ad_name)** — 같은 매체·주차·소재는 한 번만. 재업로드 중복은 DB 레벨에서 무시된다.
- **payload가 JSONB인 이유**: 매체마다 지표 스키마가 다르고(메타 ~14종, 몰로코 ~20종, 구글 ~15종) 새 지표가 계속 생긴다. 컬럼 분리 시 대부분 NULL인 25+ 컬럼과 지표 추가 때마다 DDL 변경이 필요해진다. 사이트는 행 전체를 통째로 읽어 브라우저에서 집계하므로 컬럼 단위 쿼리 이점도 없다. 식별·필터 키(channel/week_start/ad_name/업로더)는 정식 컬럼으로 분리되어 있고, 자주 보는 수치는 generated column으로 노출한다 — "쿼리는 컬럼, 내용물은 JSONB" 하이브리드.

payload 필드(합집합): `비용, 노출 수, 클릭 수, 어트리뷰션 수, 활성 유저 수, 신규+재활성 유저 수, _m_installs, _vcrNum, _vcrDen(완주율 분자/분모), _v25~_v100(동영상 25/50/75/95/100% 구간별 재생수 — 있으면), _g_interactions, _g_trueViews, _g_conversions, _g_allConv, _g_convValue` + **유저 질(AF 코호트)** `_q_retD1Base/_q_retD1Users, _q_retD7Base/_q_retD7Users(D1·D7 잔존 코호트 분모/분자), _q_revD0/_q_revD7(코호트 매출 KRW), _q_afInstalls(AF 신규 설치), _q_reAtt(재어트리뷰션), _q_reEng(재참여)` + 문자열 `_m_url, _m_ctype, _m_res, _m_group, _q_campaign, _g_assetStatus, _g_assetType, _g_status, _g_level, _g_url, _g_assetId, _g_adGroupId, _g_campaignId` + **통합 키(외부 배치가 채움 · 전 매체 공통)** `_name`(표시 이름), `_res`(해상도), `_ar`(비율), `_g_resSrc`(구글 해상도 출처 `asset_name`|`orientation`), `_m_resReal`/`_m_resName`(몰로코 ffprobe 실측 / 파일명 표기), `_svc`(서비스 분류) + **구글 애셋 보고서 건수** `_g_assetInstalls`(애셋 귀속 설치), `_g_inAppActions`·`_g_viewThroughConv`(**이벤트 수** — 유저 수 아님), `_g_assetState`(애셋 상태) — 5·6-1·6-2절 참고

### 유저 질(AF 코호트) 데이터 — 주간 통합 소재 리포트
- **출처**: 수퍼셋 크리에이티브 대시보드 dataset 내보내기(`week_start,channel,creative_name,…,cost_krw,…,ret_d1_*,cohort_revenue_*,af_installs,re_engagements,video_play_*`). 몰로코(`moloco_int`)+메타(`Facebook Ads`)가 한 파일.
- **자동 반영**: 사이트가 이 형식을 자동 감지(`isQualityExport`)해 채널별로 분리 파싱(`parseQualityExport`) → 누적·저장. 관리자가 파일만 떨어뜨리면 됨. ₩1,500 미만 행 제외, 파생지표(잔존율=Users/Base, ROAS D7=revD7/비용)는 로드 시 재계산.
- **활용**: 표 '질' 컬럼 그룹(D1/D7 잔존·ROAS D7·신규 설치(단가)·재참여(단가)) · 효율지도 축 · 상세 '유저 질' 탭(잔존 vs 중앙값·주차 추이·코호트 매출·유입 구성·표본 신뢰) · **채점: D1 잔존율 — 몰로코 6%·메타 22%**(SPEC_EVIDENCE den=retD1Base·n0=150, 데이터 없는 매체는 가용성 게이트로 자동 제외) · 자동 해석 '유저 질 최고' 라인.
- 2026-07-10 일괄 마이그레이션: 몰로코 11,357 + 메타 863행 업서트(주간 최신 2026-06-29 포함).
- **2026-07-11 스키마 정리**: CR 테이블 전부 `sr_` 접두사로 통일(`weekly_creative_stats`→`sr_weekly_creative_stats` 등). 프론트는 RPC(함수)로만 접근하므로 함수 이름/시그니처는 그대로 → **사이트 무변경**. RLS 꺼진 채 공개 노출되던 7/10 백업 테이블 2개 + CR 무관 빈 테이블 3개(site_data·persona_site_state·creative_rule_snapshots) 삭제. `creative_names`(19행)는 CR 미사용이나 타 앱 소유 가능성으로 보존.

### sr_scoring_v2 — 정제 채점 뷰 (2026-07 개편 · 분석/BI 전용)
- `supabase/migrations/20260714155424_creative_reporter_scoring_v2_view.sql`(+`155525` 잠금)로 반영된 **읽기 전용 뷰**. 과집계(홈방문·전환) 제외, `nr_users`(AUU)·`ecpa_nr`(신규+재활성 eCPA)·`cpm`·`ctr_pct`·`ret_d1/d7_pct`·그룹 키(`g_adgroup_id` 등)를 노출 — 프론트 채점 정의와 동일한 서버측 원장(교차검증·슈퍼셋용).
- **프론트는 이 뷰를 직접 조회하지 않는다**(기존 RPC 유지 — 03 결정 로그 D7). `security_invoker=true` + `anon/authenticated` revoke로 비밀번호 게이트 우회 차단(Supabase 기본권한이 신규 객체에 SELECT를 자동 부여하는 것 방지).

### sr_kv — 보조 저장소 (k, v jsonb, updated_at, updated_by)
| 키 | 내용 | 채워지는 경로 |
|---|---|---|
| `gmap` | `{adgroup:{id:이름}, campaign:{id:이름}, asset:{항목ID:공식이름}}` | 이름 매핑 CSV·광고그룹 보고서 드롭, 이미지 매칭 배치 |
| `ginfo` | `{광고그룹ID:{nm,cpNm,st,op,rsn,tcpa,cost,…,v25~v100,from,to}}` | 광고그룹 보고서 드롭 |
| `ocr` | `{항목ID:이미지에서 추출한 광고 카피}` | 비전 OCR 오프라인 배치(신규)·PaddleOCR(과거) |
| `ytt` | `{유튜브ID:영상 제목}` | 사이트가 로드 시 자동 조회(noembed) 후 저장 |
| `umetrics` | 유저 단위 실증 지표(주간 갱신, 유저 ID 무저장) — `weeks.{주차}.{cohort,newUsers_maugrowth}`(설치 코호트 실방문·신규 실유저), `trend_new_users`·`trend_d7`(주차별 신규·D1/D7), `d30_w*`(코호트 D30 주간 방문), `reeng_byCreative`(소재별 유효 복귀·단가), `lifecycle`(소재 수명·피크·최대 증액 — 구글 키는 `youtube_{영상ID}`), `glabel_w*`(구글 실적 라벨 분포), `mau_official_*`·`mau_*`·`mau_hoian_*`(MAU 3정의 — 합산 금지), `sessions_mau_*`(설치 기여 MAU·고착도), `reeng_w*`(매체 유효 복귀·자연 기준선), `uninstall_*`(설치 대비 삭제), `cost_2w_ssot`(2주 총비용 SSOT) | BigQuery·karrotmetrics 외부 배치 적재 — **사이트는 `cr_kv_get` 읽기 전용**(부팅 kv 번들에 편승, IndexedDB 부팅 캐시 포함, 실패·스키마 불일치 시 콘솔 경고만 남기고 조용히 비활성). 표시 지점: ① 분석 탭 카드 3장(카드가 뜨면 파생 요약 타일 `keyrow`는 자동 숨김 — 중복 방지)(MAU와 페이드 기여+회원계열 보조 눈금 · 매체별 MAU(설치 기여) · 설치 대비 삭제율) ② **유효 복귀 차트 — 클릭 접촉 단일 잣대**(`reeng_w*.touch_all_campaign`: 매체별 `click_pct`/`imp_pct` 분리 실측). 매체마다 기여 인정 방식이 달라 액면 비교가 불가했던 것을 **클릭 접촉 하나로 통일**해 굵은 막대로 비교(Meta 84.8 · Google 54.5 · Moloco 45.4 · 자연 기준선 36.1 세로점선), 노출까지 인정했을 때의 값은 같은 막대의 **연한 연장분**으로 병기(Google 54.5→80.6로 부풀림이 가장 큼 · Moloco는 노출 기여 0건 · Meta는 84.8→85.5로 거의 동일 — 즉 메타가 높은 주된 이유는 뷰스루가 아니라 타깃 선택편향). 그 아래 소재별 점(크기=되돌린 유저)은 `reeng_byCreative` 기준이라 **같은 매체 행 안에서만** 비교 — 몰로코 내부 3배 격차(20~22% 대형 영상 vs 61~64% 수수료 소구)가 여기서 드러남 ③ 구글 선택 시 실적 라벨×비용 스택바 ④ 사이드바 매체 '유효 복귀' 배지(기준선 눈금, 메타는 빗금+○) ⑤ 소재 상세 '실유저(주간)' 블록 — 코호트 스탯(+D30)·신규/D1·D7·D30 주차 추이 미니차트·소재별 유효 복귀(기준선 눈금)·라이프사이클 타임라인(개시→최근, 피크▲, 최대 증액×배수, 진행중 점). 키는 매체\|소재 NFC 정규화(제로폭 제거), 구글 코호트는 "[그룹] 광고그룹명", 값 없으면 미렌더 |

### sr_users — 사용자 계정과 승인 워크플로
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | bigint identity | PK |
| daangn_name | text | 사용자명(영문 시작 2~24자 영문·숫자). 앞으로 수정·제작·즐겨찾기 등 행위의 서명(수정자) 값 |
| name_lower | text **generated** unique | `lower(daangn_name)` — 대소문자 무관 유일성(사칭 방지) |
| pw_hash | text **unique** | 비밀번호 sha256 해시. 로그인·게이트가 비번만으로 사용자를 식별하므로 전역 유일 |
| pw_enc | bytea | 비밀번호 **복호화 가능 암호문**(pgcrypto pgp_sym, 키는 서버 함수 본문에만). 관리자가 비번을 열람·관리하기 위한 용도 — 관리자 게이트 RPC 안에서만 복호화 |
| status | text | `신청함`(가입 신청, 로그인 불가) · `승인됨`(로그인·데이터 접근 가능) · `거절됨`(로그인 불가, 기록 보존·재승인 가능) |
| **role** | text | `viewer`(보기 전용, 기본값) · `editor`(저장·수정 가능) · `admin`(에디터 상위 — 소재 이름 변경까지). 관리자가 admin.html에서 지정. 현재 admin은 hansy만 |
| created_at·reviewed_at·reviewed_by | | 신청 시각 · 승인/거절/권한 처리 시각·처리자 |

- **비밀번호만으로 로그인**: 입력 비번의 sha256 해시로 사용자를 찾아 이름·상태·권한을 반환(`cr_login`). 그래서 pw_hash를 전역 유일로 강제(가입 시 중복 비번 거부).
- **레거시 `0715`는 이름 없는 뷰어 하드코딩 로그인** — cr_login이 `{viewer:true}`를 반환(이름 없음), 데이터는 읽되 저장·수정은 불가. sr_users 행이 아니므로 가입 시 예약 비번 `0715`는 거부.
- 권한 모델: **뷰어**(0715 또는 role=viewer 사용자) = 읽기 전용 · **에디터**(승인됨 + role=editor) = 저장·수정 가능 · **관리자**(승인됨 + role=admin) = 에디터 권한 + 소재 이름 수동 변경(`/namechange`). 관리자는 에디터 권한을 포함(canEdit=true). 소유자는 계정을 만들어 admin.html에서 자신을 에디터/관리자로 승인. 관리자용 로그인 계정 `admin`(editor) 시드. **관리자 권한(admin role)은 admin.html 마스터 게이트(별도 시크릿)와 다른 개념** — role=admin은 앱 내 최상위 사용자 등급, `_cr_check_admin`은 계정 관리 콘솔용 마스터 비번.

### sr_user_marks — 즐겨찾기 / 내 소재 (개별 계정 단위)
| 컬럼 | 설명 |
|---|---|
| user_name | 마크 소유자 daangn_name |
| channel · ad_name | 대상 소재 (매체, 소재 식별자) |
| kind | `fav`(즐겨찾기, 비공개) · `mine`(내 소재, 등록자 공개) |
- UNIQUE(user_name, channel, ad_name, kind). RLS deny-all — RPC로만.
- **뷰어도 마크 가능**(계정만 있으면). 0715는 계정이 없어 불가. 쓰기 게이트가 아니라 `_cr_uname(pw)`로 비번→사용자 도출(0715/미존재는 null→거부).
- `cr_marks_load`는 **내 소재는 전원 공개(등록자 이름 포함)**, **즐겨찾기는 본인 것만** 반환(프라이버시).

## 3. 보안 모델

- 세 테이블 모두 **RLS deny-all**: anon 키로는 SELECT/INSERT 자체가 불가능.
- 모든 데이터 접근은 **SECURITY DEFINER RPC**를 통해서만 하고, 각 RPC 첫 줄에서 `_cr_check_pw(pw)`가 비밀번호를 검사(불일치 시 예외).
- **읽기 게이트 `_cr_check_pw`**: 입력 비번이 레거시 `0715` 이거나 **승인됨 사용자의 비번**이면 통과(읽기). 신청함·거절됨은 차단.
- **데이터 저장 게이트 `_cr_check_admin_role`** (2026-07-11): `cr_save`(주간 성과)·`cr_kv_merge`의 드롭 유래 키(gmap·ginfo·ocr 등)는 **승인됨 + role=admin(현재 hansy)** 만 통과. 에디터·뷰어의 드롭은 화면 분석만 되고 저장은 서버가 거부(프론트 `isAdmin` 게이트 + 안내 토스트). 예외: `ytt`(유튜브 제목 자동 캐시)만 에디터 허용(`_cr_check_editor` — admin 포함하도록 정상화).
- 클라이언트의 publishable key는 공개되어도 되는 값(설계상 공개키). 실질 게이트는 비밀번호.
- 비밀번호는 브라우저 sessionStorage(탭 단위)에만 저장(`crpw`) — 새로고침 유지, 탭 종료 시 소멸. 로그인한 daangn name은 `crname`(탭)·`cr_uploader`(localStorage, 기기)에 저장돼 업로드·수정 서명에 쓰인다.
- **관리자 게이트**는 사용자 비번과 완전히 분리된 별도 시크릿(`_cr_check_admin`). admin.html에서 런타임 입력만 하고 **리포지토리엔 저장하지 않는다**(GitHub Pages 공개 파일). 관리 RPC(`cr_admin_*`)만 이 시크릿으로 게이트.
- 회원가입·로그인은 anon 키로 공개 호출 가능(신청은 누구나, 로그인은 승인·비번 필요) — 기존 보안 태세와 동일.

### 로그인·가입 흐름
1. **가입**: 랜딩 '회원가입' → daangn name(영문 시작 2~24자)·비번·비번확인 → `cr_register`(신청함 적재). 이름/비번 중복·형식 오류는 서버가 거부(`name_taken`/`pw_taken`/`name_invalid`/`pw_weak`). 성공 시 "관리자 확인 후 가입이 승인됩니다".
2. **관리자 처리**: admin.html에서 신청함 → 승인됨/거절됨. 거절은 삭제가 아니라 상태 저장이라 언제든 재승인 가능.
3. **로그인**: 비밀번호만 입력 → `cr_login`이 `{found,name,status,role,viewer}` 반환. 인사(탭당 1회) — 0715 뷰어="뷰어 권한으로 로그인했어요 👀"(이름 없음) · 승인된 사용자(에디터·뷰어 공통)=**시간대별 랜덤 인사** "환영해요 NAME!"(`greetingFor`) · 신청함="아직 관리자 승인 대기 중이에요" · 거절됨="가입이 거절된 계정이에요" · 미존재=흔들기. (모든 토스트는 당근 보이스 해요체)
   - **로그인 시엔 인사 토스트만**: 첫 로그인(탭당 1회, `willGreet`)이면 `cloudUnlock`의 "☁️ 저장소를 열었어요…" 로드 토스트를 생략하고 환영 인사만 띄운다(예전엔 로드 토스트+환영 두 개가 겹쳐 떴음). 새로고침 자동 재접속(`silent`, 이미 인사함)에선 로드 토스트가 그대로 뜬다.
   - **시간대별 인사(`GREETINGS`/`greetingFor`)**: 분 단위 경계 — 새벽 00–05 · 이른아침 05–09 · **출근 09:00–11:30** · **오전근무 11:30–12:30** · **점심직전 12:30–13:00** · **점심 13:00–14:30** · **오후근무 14:30–18:00** · 저녁 18–22 · 밤 22–24. 각 구간에 3~4개 문구를 두고 랜덤 선택. 브라우저 로컬 시각(`new Date`) 기준.
- **부팅 캐시(2026-07-31 — 로그인 속도·실패 개선, 당일 v2로 강화)**: 매 접속마다 `cr_load` 전체(실측 약 11.5MB JSON·2만 행)를 다시 받던 것이 로그인 지연·간헐 실패(30초 타임아웃)의 원인 → **IndexedDB(`cr_cache`/`boot`)에 rows+kv 번들+시그니처를 캐시**한다(localStorage는 5MB 한계라 배제. IndexedDB는 **브라우저별·기기별 영구 저장**이라 새 탭·새로고침·브라우저 재시작에도 유지 — 사라지는 건 브라우저 데이터 삭제나 다른 브라우저/기기뿐). **v2 — 캐시가 있으면 네트워크를 기다리지 않고 즉시 렌더**(체감 = IndexedDB 읽기 한 번, 수백 ms): 수동 로그인은 `attemptLogin`(cr_login)이 비번을 이미 확인했고 자동 재접속의 저장 비번도 직전 세션에 유효했던 값이므로, `cr_status`(비번 재검증+서버 시그니처=총 행수+최근 업로드 시각)는 **백그라운드**에서 돈다 — 비번이 회수됐으면 화면을 회수하고 로그인 화면으로, 시그니처가 다르거나 캐시가 24시간 묵었으면 백그라운드 전체 로드(타임아웃 120초)로 화면·캐시 갱신+토스트, 무응답(408)이면 📴 안내 후 캐시 화면 유지. 월요일 11시 자동화든 수동 업로드든 '서버가 달라진 순간'을 시그니처가 잡으므로 요일 가정 없음. **콜드 스타트(이 브라우저 첫 접속)도 단계 로드**: `cr_status` 후 `cr_load_part(pw,p_since)`로 **최근 16주만 먼저**(실측 3.7MB — 전체의 1/3, 기본 기간 3달=13주가 이걸로 완결) 받아 첫 화면을 띄우고, 과거분은 `cr_load_part(pw,p_before)`로 백그라운드 합류 후 **전체가 모였을 때만 시그니처와 함께 캐시**(과거분 실패 시 시그니처 없이 저장 → 다음 접속에 자동 보완. `cr_load_part` 오류 시 종전 `cr_load` 전체 로드로 폴백). 관리자 드롭 저장 후 재로드(`cloudRestore`)·백그라운드 갱신은 `cloudFullLoad`가 캐시도 함께 갱신.
- **비밀번호 규칙**(`_cr_pwok`): **4자 이상**(복잡도 요구 없음). **같은 비밀번호로 다른 계정 생성 금지**(pw_hash 전역 유일 → register·admin_create·setpw 모두 `pw_taken`로 차단 → "다른 걸로 정해 주세요"). 예약비번 `0715`만 별도 거부.
- **새 가입 신청 알림**(관리자 전용): admin.html이 열려 있는 동안 15초 폴링해 새 신청 시 토스트+브라우저 알림, **거절은 확인창 없이 즉시**. (메인 화면에는 알림 없음 — 관리자만 봐야 하므로)
- **관리자 페이지**: **한 줄 행 표**(컬럼명 '이름'), 비밀번호 열은 평소 ●●● **호버 시 표시**(클릭 복사), 이름 **✎수정**(cr_admin_set p_name). 권한은 **뷰어/에디터 2토글**(승인 기본 viewer) — role=admin은 콘솔에서 부여·강등 불가, 주황 `관리자` 태그로만 표시. **대기 버튼 없음**(승인·거절 안 누른 신청함=대기). **신청일·처리는 '상세 보기' 체크 시에만** 표시. 반응형 열 숨김: ≤860 비밀번호 → ≤660 비번변경·✎ → ≤520 권한(이름+승인/거절 최우선 유지). ＋계정 추가·비번변경.
- **즐겨찾기 / 내 소재**(로그인 계정, 뷰어 포함 · 0715 제외): 소재 이름 우측 별 버튼 2종 — ★ 즐겨찾기(켜면 노랑) · 체크 인장 내 소재(켜면 하늘색). **표시 시(on) 별은 호버 없이 상시 노출**, 미표시는 호버 시에만 회색. **즐겨찾기는 별만**(칩·글자 없음) · **내 소재는 남이 등록한 것만 등록자 이름 칩**(본인 것은 켜진 하늘색 별로 충분하므로 칩 생략). 별은 **전체 목록·그룹 행·상세의 "같은 그룹 내 비교" 목록** 모두에 표시. 좌측 nav "보기": 전체 / 내 소재 / 즐겨찾기 필터.
  - 마크는 로그인 직후 비동기(`cr_marks_load`)로 채워진다. 최초 표는 `MARKS.me`가 아직 없는 채로 그려지므로, 마크 로드가 끝나면 **현재 탭과 무관하게 표를 다시 그려**(`loadCloudRows`) 별·칩을 채운다. (예전엔 `mainTab==="table"` 게이트에 막혀 기본 탭 `analysis`에선 로그인 직후 전체목록 별이 안 보이던 버그가 있었음)
- **내 소재 등록 대상(관리자 전용 드롭다운)**: 표 툴바의 🔖 단일선택 드롭다운(`#mineAsMsel`, 상태 `mineAs`)에서 로스터 타인을 고르면, 이후 **인장 별 토글·"내 소재" 보기 필터가 그 사람 기준**으로 동작한다. 남을 고른 상태의 별은 본인용 `cr_mark_set` 대신 **`cr_admin_mark_set`**(특정인 이름의 mine 마크 대신 등록/해제)로 저장되고, 대상이 남이면 인장 별을 **주황(`.as`)**으로 구분한다(등록자 칩으로도 확인). '나 (본인)'로 되돌리면 원래대로. 비관리자에겐 드롭다운이 숨겨지고 `mineAs`는 항상 무시된다. (연필 팝오버가 개별 소재 다인 편집 경로라면, 이 드롭다운은 여러 소재를 그 사람 이름으로 연속 태깅하기 위한 경로)
- **그룹 마크(파생·일괄)**: 그룹뷰에서 그룹 별을 누르면 멤버 전원을 일괄 토글(`cr_mark_set_many`). 그룹 상태는 **저장하지 않고 멤버에서 파생** — 멤버 전원이 표시면 그룹도 표시로 보이고, 멤버 하나를 개별 해제하면 그룹 표시도 자동 해제. 표·비교 목록은 전체 재렌더 없이 제자리 갱신(`refreshMarksUI`)해 열린 상세가 닫히지 않는다.
- **제작자 로스터**: 제작자(내 소재 등록자)는 항상 고정 로스터 **vin·mia·tank·hansy·marin·jace** 에서만 고른다(직접 입력 없음). 연필 팝오버의 제작자는 로스터 토글칩(복수), 필터는 로스터 6 + **기타**(로스터 제작자 없음). (기존 `admin` 등록분은 마이그레이션으로 `hansy`에 이관)
- **소재 편집(관리자, 연필 팝오버)**: 별(즐겨찾기·내 소재) 오른쪽 **연필 버튼**(관리자·개별 소재만, 호버 노출) → 그 소재의 **이름·서비스 분류·제작자** 를 한 팝오버에서 수정. 저장 시 이름=`cr_names_merge`(kv `nameovr`), 서비스=`cr_svc_merge`(kv `svcovr`, ''=자동 복원), 제작자 로스터 토글 diff=`cr_admin_mark_set`(특정인 mine 마크 대신 등록/해제). 표시 이름 우선순위 최상위, 서비스 오버라이드는 `svcOf`·드롭다운·서비스 칩(주황)에 즉시 반영.
- **소재 이름 일괄 변경(관리자, `/namechange`)**: 검색창에 `/namechange`+엔터 → 모든 소재명 contenteditable, 다시 `/namechange`로 저장(`cr_names_merge`). 저장 전 이탈은 `beforeunload`로 붙잡음. (연필 팝오버가 개별 편집의 주 경로, `/namechange`는 일괄용)
- **서비스·제작자 복수선택 드롭다운 필터**: 툴바에 `전체 서비스`·`전체 제작자` 2종(체크박스 복수선택, 팝업 유지). 서비스=키워드 6버킷+기타(관리자 오버라이드 우선). 제작자=로스터 6+기타(항상 노출). 개수는 현재 화면(개별/그룹) 기준.
- **자료 추출(사이드바 `내 자료 추출하기`)**: 중앙 플로팅 모달 — **제작자**(모두·로스터 단일) · **매체**(가로 세그먼트, 순서 모두·몰로코·구글·메타, 복수·모두=전체) · **기간**(가로 세그먼트 1달·3달·**올해**(당해 1월~)·전체·**직접 설정=정확한 시작~종료일 date picker**) · **비교 데이터 3단**(없음/요약만/전체 표 — 기본 **요약만**: B 섹션에 비교군 기준선 한 줄 + 지표별 중앙값·25/75백분위 통계표 + 상위 3개 참고만 담아 전체 표 대비 텍스트를 대폭 절감, 제작자=모두면 없음 강제) · **최소 점수**(없음/40+/50+/60+/70+ — 미만·무점수는 표에서만 제외하고 **요약 통계는 전체 기준 유지 + 제외 수 명시**로 체리피킹·AI 혼동 방지). 순위는 `#r/N`(그 매체·기간 채점 N개 중 r등). 모달·버튼은 아이콘 없는 미니멀, 제작자는 4열 그리드(모두·vin·mia·tank / hansy·marin·jace). 매체별로 그 기간에 맞춰 **재집계·재채점**(dataset 복제 후 `scope()`, 절대 구간은 `scopeRange()`)한 소재 성과를 **AI가 읽기 좋은 Markdown**으로 내려받음. 매체마다 A(대상 제작자)·B(동조건 타 제작자 비교군, 체크 시) 섹션으로 분리하고 각 소재는 자기 행에만 지표를 담아 **절대 혼용되지 않게** 한다. 점수는 매체·기간 비교군 상대치라 매체 간 직접 비교 금지를 헤더에 명시. (CSV 넣기 버튼은 아이콘으로 축소 + 드래그드롭 유지)
- **OCR 마크**: 소재명 옆이 아니라 **상세보기 미리보기의 애셋 URL 왼쪽**에 표시. **Live**는 소재명 왼쪽 **초록 점**(글자 없음).

## 4. 파일 인식과 저장 파이프라인

드롭된 파일은 이 순서로 분류된다:

1. **구글 확장 소재 연결 보고서** — 헤더에 `애셋 상태`+`확장 소재`. `주` 컬럼(주간) 파싱, 지표 매핑(비용/노출수/클릭수/설치/인앱 액션/전환 등 → 내부 키).
2. **몰로코 크리에이티브 리포트** — `creative_preview` 또는 `ad_name`+`creative_type`. 미리보기 CDN 링크·타입·해상도·그룹 추출. **네이티브 영상 오등록 보정**: 리포트가 완주율을 제공하는데 `creative_type`이 VIDEO인 소재의 첨부가 이미지 파일이고 완주율이 전 기간 비어 있으면 실제 노출물을 이미지로 보고 이미지로 재분류(칩 `이미지*`·유형 '이미지(영상 등록)'로 표기). 완주율이 찍혀 있으면 미리보기만 썸네일인 진짜 영상이므로 유지, 완주율 컬럼 자체가 없으면 판단 보류.
3. **일반 성과 CSV(메타 등)** — `date`+`ad_name`(또는 세트/그룹 레벨 컬럼). `thumbnail_url` 류 컬럼이 있으면 미리보기 자동 연동. `동영상 … 25/50/75/95/100%` 재생수 컬럼이 있으면 자동 인식해 `_v25~_v100`으로 누적 — 상세 '영상 시청' 탭의 구간별 유지 곡선 데이터(율·평균·시간·비용류 헤더는 제외, 횟수만).
4. **광고그룹 보고서** — 헤더에 `광고그룹 상태`+`광고그룹 ID`. 그룹 메타+누적 성과+영상 재생 퍼널을 `ginfo`로, 이름을 `gmap`으로.
5. **이름 매핑 CSV** — `광고그룹 ID`+`광고그룹` / `캠페인 ID`+`캠페인` / `항목 ID`+`애셋` 쌍. 제목 줄이 앞에 있는 UI 내보내기도 지원.

**매체 판별 우선순위**: ① 리포트 형식 자동 감지 → ② 미리보기 URL 도메인(adsmoloco→Moloco, googlesyndication/youtube→Google, fbcdn→Meta) → ③ 드롭 위치 → ④ 파일명 접두(meta_/moloco_/google_).

**구글 AEO/ACE 분리**(클라우드 로드 시): 구글은 캠페인 유형이 **AEO(신규·설치 최적화)**와 **ACE(리타겟팅·인앱액션)**로 나뉘어, 각각 성과·단가 기준이 달라 매체를 분리한다. `loadCloudRows`에서 각 소재의 `_g_campaignId`를 `gmap`(kv) 캠페인명과 맞춰(`Google_AEO_…`/`Google_ACE_…` 토큰) `_ch`를 **`Google AEO`·`Google ACE`**로 배정(`googleSubChannel`), 유형 미상은 `Google` 유지. **캠페인 ID 누락 행 폴백 2단(2026-08-04)**: 2026-08-03 첫 auto-weekly 구글 업로드가 `_g_campaignId` 없이(게다가 ad_name을 URL이 아닌 애셋 제목으로, 제목 충돌은 U+200B 증식으로) 저장돼 '유형 미상 구글' 유령 매체가 생겼음 — DB는 CSV 경로와 동일 형태(ad_name=확장소재 URL·ACE만 U+200B 1개·소재×유형 집계·campaignId 포함)로 재구성해 수리(비용 총합 보존 검증)했고, 클라이언트는 ① 로드 시 전체 행에서 만든 **광고그룹→캠페인 사전**(ag2c — 같은 그룹의 다른 주가 아는 캠페인) ② **광고그룹 raw 이름 토큰**(ACE 우선, UA 접두≡AEO — `name:` 키 광고그룹 포함)으로 분류를 복원한다. 두 단서 다 없을 때만 `Google`(추측 안 함). 루틴 측 규칙은 docs/WEEKLY_SYNC_TASK.md '구글 소재' 절에 명문화. 이후 매체 세그먼트·집계(`aggByChannel`)·`scope`·채점이 하위 매체별로 독립 동작한다(라벨 `구글 AEO`/`구글 ACE`, 추출 모달 순서도 구글 사이). **단가 기준(2026-07 확정)**: AEO = **신규 단가**(`_g_cpFirstOpen`, 비용÷first_open) · ACE = **홈 단가**(`_g_cpHome`, 비용÷홈 도달 — 기본, `gHomeEff` 토글로 전환수 CPA) — ACE '전환수'는 소재마다 액션 구성이 다른 이벤트 뭉치라 기본 기준에서 제외(`gPrimaryKey/gCostLabel`이 media·토글로 분기). 파일 드롭 즉석 분석은 아직 미분리(클라우드 대시보드 한정).

**저장 규칙**:
- 주간 리포트만 저장소 누적. 월간·일간·기간미상·매체미상은 **임시 분석 모드**(배너 표시, 저장 안 함, ☁️ 클릭으로 복귀).
- (주차,소재) 병합 그레인으로 합산 광고비 ₩1,500 미만이면 분석·저장 모두 제외.
- 뷰 누적도 DB와 같은 규칙: 이미 있는 (주차,소재)는 유지, 새 것만 추가 — 재드롭해도 이중 집계 없음.

## 5. 표시 이름 시스템 (ID/URL → 사람이 읽는 이름)

`displayNameOf(entity)` 우선순위:

1. **그룹 행** → `groupPrettyName`: 이름을 `_`로 분절해 `중고거래·shortform·2601` 형태로. `maugrowth`는 상수 접두라 생략, 그 앞의 다른 접두(`Google UA` 등)만 표시. 서비스 토큰은 한글 사전(VERTICALS: fleamarket→중고거래, realty→부동산, jobs→알바 …)으로 변환.
2. **관리자 수동 이름** — `nameovr[매체+원본명]` (`/namechange` 편집분이 항상 최우선)
3. **통합 키 `payload._name`** — 전 매체 공통 표시 이름. 구글=애셋 이름(영상 제목 / 이미지 원본 파일명), 몰로코·메타=`ad_name`. **소재 이름은 이 키가 유일한 출처이고, `ad_name`은 DB 조인 키로만 쓴다**(`unifiedNameOf` — `_name`이 URL이면 백필 이전 행이므로 이름으로 취급하지 않고 아래로 넘긴다).
4. **공식 애셋 이름** — `gmap.asset[항목ID]` (이름 매핑 CSV 또는 이미지 매칭 배치가 채움)
5. **OCR 이름** — `ocr[항목ID]` (이미지 속 광고 카피, `OCR` 마크 부착 — 과거 배치분 폴백. `_name`이 있으면 OCR 마크를 붙이지 않는다)
6. **리포트 애셋 이름** — `payload._g_assetName` (2026-07-31: 주간 루틴 [3]이 애셋 스프레드시트의 '애셋 이름'을 같은 키로 저장, 수동 드롭 리포트에 '애셋 이름' 열이 있어도 파싱·저장. **신규 소재는 이걸로 자동으로 이름이 생기므로 OCR 배치를 새로 돌릴 필요가 없다** — 실측: 이미지 애셋 231개 중 225개가 OCR 이름 의존이라 `ocr` kv는 과거분 폴백으로 유지)
7. **유튜브 제목** — `ytt[영상ID]` (로드 직후 전 소재 자동 조회·kv 공유)
8. 원문 (data-name·저장·병합 키는 항상 원문 유지, hover 시 원문 툴팁)

> **`_name` 백필 현황(2026-08-06 실측)**: 구글 7,499행 중 진짜 이름이 든 행은 96행뿐(고유 소재 804개 중 96개)이고 나머지는 `_name`에 확장소재 URL이 그대로 들어 있다. 화면은 이미 `_name`을 1순위로 읽으므로 **백필이 진행되는 만큼 자동으로 이름이 바뀐다** — 화면 수정은 필요 없다. 몰로코 11,951행·메타 929행은 `_name`=`ad_name`으로 전량 채워져 있다.

### 오프라인 이름 보강 배치 (2026-07-31부로 신규분 불필요 — 과거분 폴백만 유지)
> **은퇴 공지**: 주간 루틴 [3]이 애셋 스프레드시트의 '애셋 이름'을 `payload._g_assetName`으로 자동 저장하고 화면이 이를 표시 폴백으로 쓰므로, **신규 소재에 OCR 배치를 다시 돌릴 필요가 없다**. 아래 배치는 루틴 도입 전 소재(이미지 애셋 231개 중 225개가 `ocr` kv 의존, 2026-07-31 실측)의 이름을 지키는 폴백으로만 남는다 — `ocr` kv(12KB)는 삭제하지 말 것.
- **비전 OCR(과거 방식)**: 이름이 `tpc.googlesyndication.com/simgad/…` URL로 남은 구글 이미지 애셋을 사람이 읽을 헤드라인으로 채운다. **사이트 접속과 무관한 오프라인 사전 채움**이 원칙 — 브라우저에서 즉석 OCR하지 않고 `ocr` kv에 미리 넣어둔다.
  - 절차: ①gap 조회(아래 SQL) → ②이미지 다운로드 → ③각 이미지를 비전으로 읽어 **가장 큰 헤드라인 한 줄만 한국어 verbatim** 추출(로고 워드마크·CTA·법적고지 제외) → ④`ocr` kv에 `{항목ID:헤드라인}` jsonb 병합(`v = v || '{…}'::jsonb`). 이 이미지들은 이미 Google 공개 광고 CDN에 게시된 라이브 크리에이티브라 노출 민감도가 낮다.
  - gap 조회: `sr_weekly_creative_stats`의 `_g_assetType`이 이미지인 distinct `_g_assetId` 중 `ocr`·`gmap.asset` 어디에도 없는 것 = OCR 필요분. **마이그레이션 직후 항상 이 조회로 0인지 확인**하고 남으면 위 절차를 돌린다.
  - 품질 주의: 크롭으로 가격/숫자가 잘린 소재는 잘못된 값(예 `0원`)을 단정하지 말고 일반 문구로. `삶은당근` 같은 브랜드 카피는 그대로 유지.
- **PaddleOCR(korean, 과거 방식·참고)**: 200장 일괄 OCR. `OMP_THREAD_LIMIT=1`, 숫자 라인 신뢰도 0.55, 박스 좌표 기하 정렬, 로고 오인 후처리. 전문(全文) 덤프라 이름이 길고 지저분 → 신규분은 비전 방식으로 대체.
- **dHash 이미지 매칭**: 몰로코 IMAGE 소재(이름 있음)와 구글 simgad 이미지의 지각 해시(9×8 dHash, 해밍 ≤6 + 종횡비 ±12%)로 동일 이미지를 찾아 몰로코의 실명을 구글 애셋에 부여 → `gmap.asset`.
- 취소: 해당 kv 키 삭제 한 번이면 전체 원복.

±12%)** ④ 정규화 소재명 완전 일치 → '동일' / ⑤ 이름 토큰 자카드 ≥0.6 + 같은 서비스 → '유사'(참고). 이미지 지문은 광고 CDN이 CORS를 안 줘 캔버스가 오염되므로 **wsrv.nl 프록시(9×8 리사이즈)** 경유로 브라우저에서 직접 계산하고 `localStorage(cr_dhash)`에 영구 캐시 — 접속 4초 후 백그라운드 프리해시(`prehashAllImages`, 동시 3·상한 400)가 채우며, 새 지문이 계산되면 열린 상세의 블록만 제자리 갱신(`refreshCrossBlock`). 소재명 정규화는 확장자·해상도·날짜·매체 상투어 토큰 제거(`nameTokensOf`). 무작정 전체 대조가 아니라 종횡비·같은 서비스 제약으로 오탐을 줄인다. 다른 매체가 없으면(단일 매체·임시 분석) 블록 자체를 그리지 않는다.
- 그룹 행도 동일 스펙으로 별도 채점(scoreGroupAgg).
- **커스텀 채점(이 기기)**: 사이드바 '도구 → ⚙ 채점 설정' 모달에서 매체별(몰로코·메타·구글 AEO·구글 ACE) **채점 지표와 비중을 직접 조절**한다(믹서형 — 슬라이더+숫자, 라이브러리 체크박스로 지표 추가/제거, 규모도 하나의 조절 대상). 저장하면 `localStorage.cr_scoring`(SCFG)에 담기고 **전 매체 재채점 → 현재 화면 즉시 갱신**. 모델은 통합 100% 풀 — reachW(규모 비중)만 분리 저장하고 효율 지표는 총점 대비 비율로 저장(저장 시 자동 100% 정규화), `runScoring`이 `raw=100·((1−rw)·E + rw·R)`로 계산(기본 rw=0.5 — 2026-07 개편). **기본값과 같으면 오버라이드 미저장** → 코드 기본을 계속 따르므로, 커스텀을 안 만진 기기·계정의 점수는 종전과 100% 동일. `specsFor`/`reachWFor`/`baseSpecsOf`가 오버라이드를 읽고, 없으면 기본 SCORING. 푸터 '매체별 가중치' 바는 현재(커스텀 포함) 비중을 총점 대비 %로 그대로 표시하고 '커스텀' 뱃지·편집 링크를 단다. ROAS·활성 eCPA 등 검증이 약한 지표는 라이브러리에서 **'고급 · 채점 비권장'** 그룹(점선 구분·회갈색 라벨)으로 분리해 여전히 추가는 가능하되 기본엔 안 든다(`MET_META[...].disc:true`). **저장 가드**: 어떤 매체든 효율 지표(비규모)가 전부 0/제거면 규모만으론 채점할 수 없어 저장을 막고(모달 하단 `#scErr` 인라인 경고 + 문제 매체 탭으로 이동), 편집하면 경고가 사라진다.

## 7. UI 구성

- **사이드바(다크) — 간결·중요도 우선**: ① **화면 전환 탭**(분석/전체 목록/AB) 최상단 — 본문 헤더에서 좌측 nav로 이동(활성=주황) → ② 필터(**매체=커스텀 드롭다운**(네이티브 select 대체, 팝업 메뉴 — 각 항목에 **데이터 보유 범위**(첫 주~마지막 주·주 수, `chDataRange`) 표기, 버튼 툴팁 동일) · **기간**=1달/3달/전체 세그먼트+아래 '직접 설정'(최근 N 주/달 · **월별 보기**(월 승자+월내 추이, 주 시작일 기준) · **날짜 범위** from~to — P6, 2026-07 회의)+아래 **자동 업데이트 상태 줄**(`renderDataRange` — "● 자동 업데이트 중 (마지막 데이터 일자)". 원 색 = 데이터 최신도: **녹색**=직전 완결 주까지 최신(일상 기본 — 월요일 정오 전엔 11시 루틴 전이라 1주 뒤도 녹색 유예), **노랑**=딱 1주 뒤(월요일 동기화 누락 의심 — 확인 필요), **빨강**=2주 이상 밀림(자동화 중단). 보유 범위 `Data saved: 범위 · N주`는 툴팁으로 이동. 현재 매체 기준, 기간 필터와 무관) · **보기**=전체/My/★ 세그먼트) → ③ **액션 행**(⚙ 채점 설정 · 자료 추출(주황) · 용어 ⓘ). 요약 KPI 패널·CSV 넣기 버튼·☁️ 저장소 줄 제거(CSV는 드래그&드롭 업로드, 새로고침은 페이지 리로드). **모바일(≤900px)**: 매체·기간·보기를 가로 3열 드롭다운으로 압축(직접 설정 입력은 필터 아래 전폭), 액션 3버튼 한 줄. 데스크톱(좁은 컬럼)은 채점 설정 한 줄+자료 추출·용어 다음 줄.
- **채점 설정 지표 카탈로그**: 집계 시 실제 파생되는 지표만 노출 — 단가류(신규+재활성/활성 eCPA·eCPI·신규 설치/재참여 단가·신규/홈 단가·CPA·CPM·CPC), 반응(CTR·완주율·신규 전환율/전환율·상호작용율·조회율·홈 도달율), 질(D1/D7 잔존·ROAS D7 AF실측·ROAS 모델). 각 지표는 **↑/↓ 방향 대신 작은 회색 한 줄 설명**(desc)만 표시(좋고 나쁨은 표·지도가 표현). MET_META에 desc, SPEC_EVIDENCE에 신규 지표 표본 축소 추가.
- **전체목록 상단 스티키 툴바(2줄)**: 툴바(`.tbar`)는 `position:sticky;top:0`로 스크롤해도 상단 고정 — 1줄=검색 · [서비스·제작자 복수선택] · 칩필터 · [라이브·비디오·이미지 세그먼트] · [그룹뷰·갤러리뷰·비활성 포함 세그먼트]. 표 헤더(`thead th`)도 `position:sticky`지만 `top:var(--tbarH)`로 툴바 높이만큼 내려 붙어 2번째 스티키 줄이 된다. `--tbarH`는 `syncTbarH()`가 `#tabTable`에 툴바 실측 높이를 심어 캐스케이드시키며, `renderQuickFo()`·resize에서 갱신. 갤러리뷰·비활성 포함은 세그먼트 버튼(체크박스 아님)으로 토글.
- **'선택됨' 표시 체계(표면별 1가지)**: 강조가 화면마다 제각각이던 것을 정리 — **탭=주황**(사이드바 네비 탭 + 채점 모달 매체 탭), **활성 필터=진회색(ink)**(서비스·제작자 드롭다운 활성·칩필터·라이브/홈도달 토글·필터 팝업 칩), **세그먼트 토글=중립 흰 알약**(비디오/이미지·그룹뷰 등). 주황은 네비/브랜드에만 쓰여 위계가 선다.
- **전역 오류 처리**: `logErr(ctx,e)`로 콘솔 집계, `window.onerror`/`unhandledrejection`에서 ResizeObserver·크로스오리진 잡음은 무시하고 그 외엔 토스트로 노출. CSV 업로드는 파일 하나 파싱 실패가 전체 배치를 막지 않도록 개별 `try/catch/finally`로 격리(실패 파일명만 수집).
- **세그먼트 탭**: 분석 / 전체 목록 / AB테스트(인식 그룹 0개면 탭 숨김). 본문은 카드 없이 흰 배경 풀폭(최대폭 1240px 중앙 정렬), 푸터는 캔버스색+간격으로 구분.
- **분석**: 요약 타일(포맷/사이즈 우위, 주간 흐름) · 효율 지도(2축 산점도 — '보기' 세그먼트로 개별 소재 또는 포맷/사이즈/형태/지면/서비스별 집계(상하 10% 트림) 전환, 가로/세로 축도 세그먼트, 범위 슬라이더. 구 '유형별 비교' 그래프는 지도에 흡수) · 주차별 추세(선택 기간 전체, 라벨 자동 솎기).
  - **효율 지도 컨트롤 바(한 줄)**: `필터`(**Live 단독 토글 버튼** + **Video/Image 세그먼트**) · **보기·가로·세로 = 드롭다운(select)** 을 가로로 나란히(`.qbar`). 보기는 **소재/사이즈/서비스** 3종만(값 2종 이상 차원만 노출). 기본 축 = 매체 채점 스펙 유도(defaultAxes): 세로 채점 1순위 단가 × 가로 성격이 다른 무조건부 상승 지표 — AEO 신규 단가×신규 전환율 · ACE 홈 단가×홈 도달율 · 몰로코/메타 eCPA×D1 잔존율 (스펙 지표 없으면 폴백 체인). Live/Video/Image는 지도에 그릴 소재 집합에만 적용(표 필터와 독립), 데이터셋 전환 시 리셋. 개별 소재 보기는 **원 위 이름 라벨 생략**(겹침 방지·호버로 확인), 유형 보기만 라벨. 원 겹침은 호버 강조(불투명도·외곽선↑)+양축 슬라이더로 좁혀 봄.
  - **주차별 추세 주 지표 토글**: 광고비/노출/클릭/설치/활성유저 중 선택(데이터 있는 지표만 노출) — 유저 반응 절대량 흐름 확인용. 효율선(단가)은 광고비 선택 시에만 함께 표시.
- **전체 목록**: 소재명 **왼쪽**에 라이브(`.lvb` — **초록 점**만, 글자 없음)·학습중(`.lrn`) 뱃지, 소재명 우측 `›` 캐럿은 제거(행 전체가 펼침 토글). 컬럼 계층(대표: 점수·**광고비**·**데려온 유저**(ACE는 '데려온 방문'=홈)·홈 방문(AEO)·채점 1순위 단가·D1 잔존(몰·메타)·CTR·완주율(몰 영상)·ROAS(참고), 헤더 +로 세부 펼침) · 창 좁으면 중요도 낮은 그룹부터 자동 숨김(fitTableCols: 참고→반응→영상→유저 질→홈→광고비 · 데려온·단가·점수 불가침 · 표 위 안내) · 기본 Live 필터(스코프 최신 집행 주 광고비>0) + 무점수(–) 소재 기본 숨김('비활성 포함'으로 표시) · GroupView(광고그룹 집계, Video/Image와 상호 배타) · 이름 아래 칩 클릭=필터(서비스·포맷·사이즈·그룹·날짜) · **제작자 칩** 클릭=그 제작자 필터 토글(‘전체 제작자’ 드롭다운과 동일). **칩은 그룹명 칩(보라)만 색을 쓰고 나머지(서비스·포맷·사이즈·제작자·날짜)는 전부 무채색(회색)** — 선택된 제작자 칩만 진회색 반전으로 활성 표시 · 60행 페이지. 점수 칸은 10단계 색(십의 자리마다 다른 색, 파랑→청록→초록→올리브→무채→황토→주황→빨강).
- **미리보기 실측 사이즈·재생시간(MDIM)**: 이름/리포트에 해상도 표기가 없는 매체(메타·구글 등)도 **미리보기에서 크기를 얻는다**. 이미지는 이미 뜨는 썸네일 `onload`의 `naturalWidth`, 영상은 상세 재생 `loadedmetadata`(+ 접속 2.5초 뒤 시작하는 스로틀 백그라운드 `preload=metadata`, 동시 2·상한 240)로 실측해 **기기 `localStorage`(`cr_mdim`)에 캐시**(서버 무접촉). 값은 디코드된 원본에서 읽어 정확하고, 프록시(wsrv.nl 리사이즈본)로 뜬 이미지는 오측 방지로 건너뜀. 새 치수가 들어오면 크기 없는 소재의 `tags.size`/`shape`를 채워(재집계 없이 현재 뷰 반영) 표 사이즈 칩·분석 '보기 → 사이즈'가 **모든 매체**에서 동작. 재생시간은 상세 미리보기에 `1080×1920 · ⏱ 0:15` 형태로 표기.
- **이름 옆 뱃지**: `Live`(초록 점 — 최신 집행 주에 광고비가 나간 소재/그룹, 전 매체 공통) · `경고`(호박색 — 구글 광고그룹 보고서상 정책 제한, 사유는 툴팁) · `학습중`(집행 2주 미만 또는 전환 30건 미만). 일시중지는 뱃지 없음 — Live 뱃지 부재로 드러나고, 그룹 상세 메타에만 '일시중지' 텍스트 표기.

## 6. 유튜브 영상 해상도 — 실측만 신뢰

유튜브 썸네일은 **어떤 영상이든 고정 규격**(`default.jpg`=120×90, `hqdefault`=480×360 …)이라 세로·가로·정사각이 한 값으로 뭉개진다. 표에 `120×90`이 무더기로 뜨던 원인이 이것이며, 썸네일 `<img>`의 natural 크기가 `imgOk → mdimEl → MDIM`으로 흘러 들어간 결과였다.

- **차단**: `mdimSet`은 유튜브 썸네일 호스트(`i.ytimg.com`·`img.youtube.com`) URL과 120×90 값을 저장하지 않는다.
- **정화**: 부팅 시 `cr_mdim`에서 과거 버전이 남긴 오염(유튜브 URL 키·썸네일 규격 값)을 **매 로드 제거**한다. 1회 플래그를 쓰면 플래그가 먼저 박힌 뒤 유입된 오염을 놓친다.
- **단일 경로**: 유튜브 소재의 해상도는 `arInfoOf`에서 **통합 키 `_res`/`_ar` → oar 실측(`YTAR`) → 구글 보고서 '방향'** 순으로만 판단하고, 썸네일 측정치·리포트 표기는 폴백으로도 쓰지 않는다(전부 없으면 미확정으로 남겨 실측 도착 때 채운다). 미리보기 소스 줄(`assetPreview`/`refreshIsleDim`)과 그룹 목록도 같은 규칙을 따른다. **oar가 1순위였던 것은 `_res` 도입 전 이야기다** — 레터박스 실측은 커스텀 썸네일에서 오판이 나므로 검증된 `_res`가 있으면 그쪽이 이긴다.

### 6-1. 해상도 통합 키 `_res`·`_ar`와 출처 표기

해상도를 **파일명에서 정규식으로 긁거나 추정하지 않는다**. 외부 배치가 매체별로 검증한 값을 `payload._res`(`"1080x1920"`)·`payload._ar`(`"9:16"`)에 넣어 주고, 화면은 그 값과 **출처**를 함께 보여준다(`resFromPayload` → `arInfoOf` → `arDispOf`/`arDispTitle`).

| 매체 | `arInfoOf().src` | 판별 | 표시 |
|---|---|---|---|
| 구글 | `gname` | `_g_resSrc="asset_name"` — 애셋 이름에 박힌 실제 규격 | 가장 정확 |
| 구글 | `gori` | `_g_resSrc="orientation"` — 보고서 '방향' 열 | 정확 |
| 몰로코 | `mreal` | `_m_resReal` 존재 — ffprobe 실측(실제 서빙 파일) | 정확 · **640 계열이 정상**이므로 1080으로 보정하지 않는다. `_m_resName`(파일명 표기)과 달라도 정상이며 툴팁이 그 차이를 설명한다 |
| 몰로코 | `mfile` | `_m_resReal` 없음 — 파일명 파싱값 | 미검증 → 칩·배지를 **회색 점선**으로 낮춤(`.chip.res-unver`/`.asset-dim.unver`) |
| 메타 | — | 데이터 없음 | **표시하지 않는다.** 소재명에 박힌 숫자를 해상도로 읽지 않는다(`mediaKindOf(e)==="meta"`면 이름 파싱 경로를 차단 — 실측: 메타 고유 소재 231개 중 이름에 크기가 든 것은 0개라 손실 없음) |

**영상은 무조건 제작 표준 규격으로 표기한다 (2026-08-06 확정).** 가로 `1920×1080` · 정사각 `1080×1080` · 세로 `1080×1920` — **실측 픽셀이 있어도 마찬가지다.** 매체가 서빙용으로 트랜스코딩하면 몰로코처럼 `640×360`·`640×640`이 잡히고 유튜브 캔버스 실측도 제각각인데, 그건 "이 소재가 어떤 규격으로 만들어졌나"의 답이 아니고 같은 소재가 매체마다 다른 해상도로 보여 **해상도 필터·타매체 매칭이 갈라진다**. `_res`는 화면비 판정에만 쓰고 표기는 규격으로 통일한다(`arDispOf`가 단일 창구 — 표 칩·미리보기 배지·그룹 목록·필터 집계가 전부 여기를 지난다. 실측값은 버리지 않고 `stdSwapOf`로 툴팁에 병기). **이미지는 1200×628·720×720처럼 규격이 실제로 갈리므로 실측·표기값 그대로.** 타매체 매칭도 한쪽이 영상이면 픽셀 대신 화면비 클래스로 비교한다.

**출처 우선순위: `_res` → `_ar` → (그 다음에야) 사이트 자체 추정.** 사이트가 스스로 만들던 값 — 유튜브 썸네일 레터박스 실측(`oar`/`YTAR`), `_g_orientation` 문자열 재해석, 소재명·리포트 표기 정규식 — 은 **오판이 많아 폐기 대상**이고, 그것을 바로잡으려고 외부에서 검증해 넣어 주는 값이 `_res`다. `_res`가 있으면 `arInfoOf`는 그 줄에서 판단을 끝낸다. 아래 폴백 사슬(oar → 보고서 '방향' → 리포트 표기 → MDIM)은 **`_res`·`_ar`가 아직 없는 행만** 지나간다 — 백필이 진행될수록 자동으로 폴백이 밀려난다.

`_res`가 없고 `_ar`만 있으면 비율만 아는 것이므로 화면비 클래스(`src="par"`)로만 쓴다.

### 6-2. 구글 애셋 보고서 지표 (`gAssetHTML`)

구글 소재 상세에만 붙는 블록. `payload._g_assetInstalls`·`_g_inAppActions`·`_g_viewThroughConv` 중 **키가 하나라도 있었을 때만**(`_gaSeen`) 렌더하고, 없으면 0%·`-`로 채우지 않고 블록을 통째로 숨긴다.

- **`_g_assetInstalls`(설치 · 애셋 귀속)** — 구글이 *애셋까지* 귀속시킨 설치만 집계된다. 합계가 광고그룹 실제 설치의 **약 3%**(실측 2.6%)라 절대 수치로 읽으면 오독이다. 모든 파생 줄에 "애셋까지 귀속된 설치만 집계됩니다(광고그룹 합계의 일부). 소재 간 비교용으로 보세요." 주석이 붙는다. **몰로코·메타의 어트리뷰션과 같은 열에 놓고 비교하지 않는다** — 귀속 단위가 다르다.
- **`_g_inAppActions`·`_g_viewThroughConv`는 이벤트 수**다. '활성 유저 수'·'신규 유저 수' 같은 유저 라벨을 붙이지 않는다(자체 점검이 `.gi-k` 라벨에 '유저'가 없음을 검증한다). ⚠️ 단, 구글 CSV 파서는 역사적으로 `인앱 액션`→`활성 유저 수`, `조회연결 전환`→`신규+재활성 유저 수` 컬럼에 싣고 있어 **표 헤더의 그 두 이름은 여전히 이벤트 수**다(표 전체·채점 스키마가 걸려 있어 이 패치에서 손대지 않음 — 별도 과제).
- **비율 4종(비용/설치·전환율(설치)·1,000회 노출당 설치·CTR·평균 CPC)은 payload에 오지 않는다.** 한 주치 비율을 여러 주 소재에 붙이면 틀리므로 **선택 기간 합산 카운트에서 그대로 나눠** 만든다. CTR·CPC는 이미 신뢰성 게이트(`CTR_PLAUSIBLE_MAX`)를 통과한 `e.CTR`·`e.CPC`를 재사용해 물리 불가값이 이 블록으로 새지 않게 한다.
- **`_g_assetState`(애셋 상태)** — DB에 아직 없어 기존 `_g_assetStatus`(사용 설정됨/삭제됨)로 폴백한다. `_g_perfLabel`(실적 등급)은 가장 최근 주 값.

> 실측 근거: `전환수 = 설치 + 인앱 액션`이 정확히 성립한다(YouTube `V0H6FVV1VZk` 1,178 + 210,310 = 211,488 · 이미지 `keyword-Basket_720x720` 1 + 1,308 = 1,309).

### 6-3. 이름이 없는 영상 잇기 — 그룹 다리 (`xmGroupBridge`)

타매체 매칭(`crossMediaMatches`)은 ① 같은 유튜브 ID ② 같은 URL ③ 이미지 지문(dHash) ④ 소재명 일치 ⑤ 이름 유사 순으로 판정한다. 구글 영상은 **이름이 아직 URL이라 ④·⑤가 통째로 막힌다** — 게다가 URL을 토큰화하면 `youtube`·`com`·`watch`만 남아 **서로 다른 영상이 '소재명 일치'로 묶이는** 오탐이 났다(`nameTokensOf`가 URL이면 빈 집합을 돌려주도록 차단).

그래서 이름 대신 **같은 그룹 안의 이미지**를 다리로 쓴다.

1. 내 그룹의 이미지가 저쪽 채널 그룹의 이미지와 지문까지 같으면(`dhashHam ≤ 6` 또는 URL 동일) 두 그룹을 같은 캠페인 계열로 본다 — `bridge: "{채널} {내 그룹}" → Map(저쪽 그룹 → 근거 이미지 수)`.
2. 이름이 없는 **영상**은 그 다리를 건너 [같은 그룹 계열 + 같은 서비스 + 같은 해상도 + 영상] 조건으로만 후보를 좁힌다.
3. 확정이 아니므로 '동일'(conf 2)·'유사'(1)와 구분되는 **'추정'(0)** 등급(점선 필)으로만 내보내고, 근거 이미지 수를 툴팁에 적는다.

**이름이 생기면 이 경로는 저절로 꺼진다** — `myTok.size===0`(이름이 URL)일 때만 다리를 놓기 때문에, `_name` 백필이 닿는 소재부터 순서대로 ④ 소재명 일치로 승격된다. 다리 캐시는 `_dhashGen`(지문이 하나 계산될 때마다 증가)으로 무효화해 백그라운드 해싱이 진행될수록 다리가 촘촘해진다.

### 6-4. 분석 탭에서 걷어낸 것 (2026-08-06)

- **`MAU와 페이드 기여` 카드**(umetCards 첫 장)와 **`유효 복귀 — 클릭 접촉 기준` 매체 비교 스트립**(reengStrip)을 제거했다. 둘 다 매체를 나란히 세워 비교하는 화면인데, 메타가 다른 잣대로 집계돼 **같은 척도 비교가 성립하지 않는다**. 잘못 읽힐 바에 안 보여주는 편이 낫다는 판단.
- `mau_official_*`·`mau_*`·`mau_hoian_*`·`reeng_w*` kv는 화면에서 더 이상 읽지 않는다(데이터는 남아 있으나 미사용).
- **소재 상세의 '유효 복귀'는 유지한다** — 같은 매체 안에서만 비교하는 값이라 잣대 문제가 없다.

### 6-5. 자체 점검 `CR_SELFTEST()`

빌드 도구가 없는 단일 HTML이라 러너 대신 페이지에 심었다. `index.html?selftest=1`로 열거나 콘솔에서 `CR_SELFTEST()`. **키가 없을 때 0·`-`로 채워지는 회귀**와 **`_res`가 사이트 추정에 밀리는 회귀**를 주 표적으로 22건을 덮는다(이름 5 · 해상도 11 · 구글 블록 4 · 타매체 토큰 2).

## 7. 소재 상세 화면 구성 (2026-08-05 개편)

**2열**로 재편했다 — `[미리보기 + 타매체 성과] | [실증·그래프]`.

- **왼쪽**: 미리보기(비율에 따라 3종 폭) 아래에 **타매체 성과**(같은 소재의 다른 매체 버전). 같은 소재끼리라 미디어와 붙어 있는 편이 자연스럽다.
- **오른쪽**: ① **비교군 내 위치**(신규) ② 실유저(주간) 실증 ③ 그래프 탭(주차별 추이·유저 질·영상 시청·포지셔닝).
- **'같은 광고그룹 내 비교' 목록은 제거**했다. 그룹 안 상대 위치는 아래 백분위가 더 압축적으로 답한다.

### 비교군 내 위치 (`peerRankHTML`)
"이 소재가 잘한 건가?"는 절대값이 아니라 또래 대비로만 답할 수 있다. **같은 광고그룹**과 **같은 서비스** 두 비교군에서 **광고비**(예산이 얼마나 몰렸나 = 머신러닝 신호)와 **실유저**(실제로 몇 명을 데려왔나)의 백분위를 한 줄 막대로 보여준다. 회색 눈금은 비교군 중앙값(항상 50%), 값은 "상위 N%"로 병기한다. 비교군이 4개 미만이면 그 행을 그리지 않고, 둘 다 없으면 매체 전체로 폴백한다.

- **실유저 기준은 표의 '데려온 유저'와 동일**하다(구글=`_g_firstOpen` 앱 최초 실행, 몰로코·메타=신규+재활성 AUU). 채점용 규모축(`reachKeyFor`)은 구글에서 노출이라 여기 쓰지 않는다 — 사용자가 표에서 보는 수치와 어긋나기 때문.

### 지표 행 문법 — 모든 블록이 같은 한 줄을 쓴다
비교군 위치·실증 스탯·서비스 도달·유효 복귀를 **`[라벨 … 값 · 등급 · 순위]`** 한 줄(`.mrow`)로 통일했다. 블록마다 다른 문법을 두면 같은 화면에서 읽는 법을 여러 번 배워야 한다.

- **막대(트랙)를 그리지 않는다.** 마커 하나의 위치로는 좋은지 나쁜지, 상위 어느 정도인지가 가늠되지 않는다는 것이 실사용 결론이었다. 판단에 필요한 값은 **값·등급·순위** 셋뿐이고, 이 셋을 행 오른쪽에 붙여 한 덩어리로 읽히게 한다(근접성). 라벨은 남는 폭을 차지해 값 블록과 자연히 분리된다(거리).
- **등급**(매우 좋음·좋음·보통·낮음)은 비교군 백분위에서 유도한다(상위 20/40/65% 경계). **순위**는 같은 백분위에서 뽑은 "상위 N%"다 — 등급과 순위가 같은 기준이라 서로 어긋나지 않는다.
- **모든 표기는 반드시 한 기준을 가리킨다.** 기준이 갈리면 "평균과 같은데 낮음" 같은 오독이 난다 — 서비스 도달도 전체 평균이 아니라 *같은 기준(basis) 소재 분포의 중앙값*으로 통일하고, 전체 평균은 툴팁 참고값으로만 둔다. 중앙값 대비 편차(±%p)도 툴팁에 둔다.
- 행은 **2열 그리드로 흘린다**(`.mrows`).
- 추이가 필요 없는 값(D1·D7·D30)은 **선을 그리지 않는다** — 수평선 두 줄은 정보가 아니다. 수치 행으로 둔다.
- 주차별 추이의 실적 라벨은 **모든 주에 채운다.** 빈칸은 "성과가 없다"로 오독되고, 막대만 보고 대강이라도 판단하려면 등급이 매 주 있어야 한다. 실측은 진하게, 실측 라벨이 없는 주(구글 외 매체 포함)는 최근 확인된 등급을 **흐린 점선**으로 구분한다.
- 선(신규 단가·신규 실유저 등)에는 **최고점과 최저점에만** 수치를 적는다. 모든 점에 붙이면 숫자가 선을 덮는다. 라벨을 위에 둘지 아래에 둘지는 **그 주에서 이 선이 다른 선보다 위인지**로 정하므로, 두 선이 교차해도 숫자가 겹치지 않는다.

### 서비스별 7일 도달 (`_svc` 기반)
모든 소재에 같은 지표를 보여주면 **부동산 소재에 중고거래 7일을 띄우는** 일이 생긴다. 소재 행의 `payload._svc`로 그 소재가 어떤 서비스를 위한 것인지 알아내, `svcmap.map`이 지정한 **주지표 하나 + 앱 접속(홈피드) + 재방문**만 보여준다.

| 소스 | 대상 | 조회 키 | 기준 라벨 |
|---|---|---|---|
| `svc7_w*.creatives` | 구글·메타·몰로코 LocalAds | `"{채널}\|{ad_name}"` (구글은 `"[그룹] 광고그룹명"`) | 신규 설치 7일 |
| `svcRe7_w*.creatives` | 몰로코 maugrowth | `ad_name` 그대로(채널 접두 없음) | 복귀 후 7일 |

- `svc7`을 먼저 찾고 없으면 `svcRe7`, 둘 다 없으면 **블록을 통째로 숨긴다**(0%나 "-"로 채우지 않는다). 조회 전 `ad_name`의 U+200B를 제거한다.
- `_svc`가 `brand`/`unknown`이면 주지표가 `home`이라 always_show와 겹치므로 자동으로 한 번만 나온다.
- **기준 라벨을 항상 표시한다.** 분모가 다른 값이라 라벨이 없으면 오독된다. 두 기준의 값을 같은 축에 섞지 않는다.
- 비교는 **같은 기준(basis) 소재 분포 안에서만** 한다. `peer_baseline_svc7`(전체 평균)은 `svc7` 툴팁의 참고값으로만 쓰고 `svcRe7`에는 언급조차 하지 않는다 — 분모가 다르다.
- 실측 예: 구글 부동산 광고그룹은 전체 재방문 7일이 73.9%로 멀쩡해 보이지만 **부동산 7일은 1.1%**다. 서비스 지표를 따로 봐야만 드러난다.

### 분포 위 위치 마커 (채움 막대를 쓰지 않는 이유)
값들이 서로 비슷할 때 **0부터 채우는 막대는 전부 비슷하게 길어져** 자리만 차지하고 변별이 되지 않는다. 그래서 실증 스탯과 비교군 백분위는 **얇은 트랙 + 위치 마커**로 그린다.

- 트랙 양끝 = 비교군 분포의 **하위 10%~상위 10%**(백분위 행은 0~100), 회색 눈금 = **중앙값**. 마커는 이 소재의 위치.
- 스케일은 **비교군 전체로 고정**한다 — 소재마다 축이 달라지면 같은 편차가 다르게 보여 오독이 생긴다.
- 분포 밖(하위·상위 10% 초과)은 끝에 붙이되 **마커 모양을 원→사각으로** 바꿔 "축을 벗어남"을 알린다(길이를 늘여 과장하지 않는다).
- 결과적으로 평범한 값은 마커가 가운데 몰려 조용하고, 특출난 값만 끝으로 가 눈에 띈다. 편차 수치(±%p)는 마커 아래 텍스트가 담당한다.

> **SVG는 viewBox가 렌더 폭보다 작으면 통째로 확대된다.** 주차별 추이는 마크업에 `width: W*1.6px`가 박혀 있어 실측 **2.73배**로 그려졌고, `font-size="6.25"`가 화면에서 17px, 선 두께가 4.9px가 됐다. 좌표계를 실제 폭(820)에 맞추고 인라인 폭을 제거해 배율 1.02로 잡았다. **새 차트를 만들 때 viewBox 폭은 렌더 폭과 같게 두는 것이 원칙이다.**

> 절대 스케일이 의미를 갖는 곳(유효 복귀 0~100%와 자연 기준선, 매체별 MAU 규모 비교)은 채움 막대를 유지한다 — 거기선 "얼마나 채웠나" 자체가 정보다.

### 차트 통합 원칙
같은 축(주차)에 놓을 수 있는 값은 **별도 차트를 만들지 않고 기존 차트에 얹는다**. 신규 실유저(umetrics)는 주차별 추이(`ispark`)에 초록 점선으로 합쳤고(소재당 몇 주치만 있는 부분 데이터라 값이 있는 구간만 이어짐), 실유저 블록에는 성격이 다른 **코호트 재방문(D1·D7·D30)** 추이만 남겼다. 재방문 추이는 라인차트라 y축을 0이 아닌 **실제 값 범위**로 잡는다(막대와 달리 0 기준이 필수가 아니고, 그래야 주 단위 변화가 보인다).

> 상세는 표 `<td>` 안에 그려지므로 **`text-align: right`가 상속된다.** 블록 루트(`.umet-strip`·`.peer`)에서 `text-align:left`로 끊어야 한다 — grid로 셀을 넓히면 이 상속이 값·라벨 우측 쏠림으로 드러난다.

## 8. 비교뷰 레이아웃 — 개수 하나에서 모든 치수를 유도

비교 소재 개수(2~8+)에 따라 화면이 크게 달라지는데, 예전엔 요소마다 폭 규칙이 따로 놀았다. 카드는 `max-width:360px` 고정이라 2개일 때 좌측에만 몰리고, 표와 차트는 화면 전체를 써서 **세로선이 어디에도 맞지 않았다.** 차트는 `window.innerWidth` 기준으로 그려져 컨테이너와 어긋나 0.58배로 축소되기까지 했다.

이제 **개수 `n` 하나에서 열 수 → 콘텐츠 폭 → 프레임 높이를 순서대로 유도**하고, 미리보기·차트·표가 **같은 폭(`.cmpm-in`)을 공유**한다.

| n | 열 | 행 | 콘텐츠 폭 | 프레임 높이 |
|---|---|---|---|---|
| 2 | 2 | 1 | 880 | 380 |
| 3 | 3 | 1 | 1200 | 300 |
| 4 | 4 | 1 | 1460 | 240 |
| 5~6 | 3 | 2 | 1200 | 222 |
| 7~8 | 4 | 2 | 1460 | 178 |

- **5~6개를 한 줄에 욱여넣지 않는다.** 3열 2행으로 접어야 카드가 읽을 만한 크기(391px)를 유지한다 — 한 줄이면 242px까지 눌려 이름부터 잘렸다.
- **두 줄로 접히면 프레임 높이를 1.35로 나눈다.** 안 그러면 미리보기가 첫 화면을 다 먹고 정작 비교할 지표가 밀려난다.
- 차트는 `R.contentW`(= 위 표의 콘텐츠 폭)를 받아 그린다. **화면 폭을 가정하면 컨테이너와 어긋난 만큼 확대·축소된다.**
- 카드 헤더는 **2줄**이다 — `[순위 · 우세도]` 줄과 이름 줄. 한 줄에 두면 좁은 카드에서 이름부터 잘린다.
- 표는 열이 많아질수록 헤더 이름을 먼저 줄인다(14→11→8자). 가로로 넘치면 오른쪽 소재가 화면 밖으로 나간다.
- **관심 소재 강조**: 미리보기 카드나 표 열에 마우스를 올리면 차트에서 그 소재의 선이 굵어지고(1.6→3.4px) 점이 커지며, 나머지는 물러난다(opacity .16). 선이 얇아 여러 개가 겹칠 때 색만으로는 "지금 보는 게 어느 것인지" 찾기 어려웠다. 카드·표·차트가 `data-ci`(소재 인덱스)를 공유해 어느 쪽에 올려도 같이 반응한다.

## 9. 주차별 실적 라벨 — 없는 주는 그 주 데이터로 다시 계산한다

주차별 추이의 막대 밑에는 그 주의 실적 등급이 붙는다. 실측(구글 리포트의 `_g_perfLabel`)이 있으면 그대로 쓰고, **없는 주는 `weeklyPerfEst()`가 그 주 데이터만으로 등급을 새로 계산**한다.

- 소재의 **현재 라벨을 모든 주에 복사하면 안 된다.** 같은 글자가 13주 내내 도배돼 "주차별" 추이라는 이름 자체가 무의미해진다. 실제로 그렇게 만들었다가 되돌렸다.
- 반대로 **빈칸으로 두어도 안 된다.** "라벨이 없다"와 "성과가 없다"는 다른 뜻인데 빈칸은 후자로 읽힌다.
- 계산식은 `estimatePerfLabels`와 동일한 `PERF_EST` 가중치(전환수 등수 0.30 + CTR 등수 0.20 + 전환수÷코호트 최대 0.30 + 광고비÷코호트 최대 0.20)를 쓰되, **비교 코호트를 그 주 안에서만** 잡는다. 구글은 같은 광고그룹(3개 이상일 때), 그 외에는 그 주에 집행된 소재 전체다. 코호트가 3개 미만이면 등급을 내지 않는다(표본이 없는데 등급을 붙이면 거짓 신호).
- 표기 구분: 실측은 **불투명·굵기 700**, 추정은 **불투명도 0.6 · 굵기 600 + 점선 밑줄**. 툴팁으로 산출 근거를 밝힌다.

검증(2026-08-06, 4개 매체 상위 10개 소재 = 438개 주차 막대): **라벨 없는 막대 0개**, 추정 등급은 매체마다 매우 좋음/좋음/낮음이 섞여 나온다(복사였다면 소재당 1종만 나왔을 것). 텍스트 잘림 0.

## 10. 화면 배율 규칙 — SVG는 0.84~1.0 밖으로 나가지 않는다

창 너비에 따라 글자·선 두께가 제멋대로 변하는 문제의 원인은 하나다. **`width:100%`인 SVG는 컨테이너 폭 ÷ viewBox 폭 만큼 통째로 확대·축소되므로, 선언한 `font-size`가 화면 픽셀과 달라진다.** 타이포 스케일(§5)을 아무리 정해도 이 배율이 흔들리면 무의미하다.

원칙: **모든 차트 SVG는 `min-width`(하한)와 `max-width`(상한)를 viewBox 폭 기준으로 함께 건다.**

| 요소 | viewBox 폭 | min-width | max-width | 실측 배율 범위 |
|---|---|---|---|---|
| `.rst svg` (유효 복귀) | 1200 | 1080 | 1200 | 0.90 ~ 1.00 |
| `.ispark-svg` (주차별 추이) | 820 | 740 | 820 | 0.90 ~ 1.00 |
| `.us-life` (라이프사이클) | 560 | 470 | 560 | 0.84 ~ 1.00 |

- **상한이 없으면** 넓은 창에서 글자만 커진다(측정값 1.02~1.10).
- **하한이 없으면** 좁은 창에서 절반으로 쪼그라든다 — `.us-life`는 뒤에 남아 있던 중복 규칙(`min-width:0`)이 상한 규칙을 덮어써 1000px 창에서 **0.49배**까지 내려갔다. 같은 선택자를 두 번 쓰면 나중 것이 이긴다.
- 그리드는 `auto-fit`을 쓰지 않고 **단계형 중단점**으로 접는다(`.umet-cards` 3→2→1 @1150/@760, `.mrows` 2→1 @1080, `.umet-stats` 4→2 @1080). `auto-fit`은 폭이 1px 변할 때마다 열 수가 바뀌어 레이아웃이 출렁인다.

검증(2026-08-06, 폭 1560/1440/1360/1200/1100/1000/900): 배율이 1을 넘는 SVG 없음, 최저 0.84, 가로 스크롤 없음.

## 11. 근접성 — 붙어 있는 것이 한 덩어리다

`[라벨 값 등급 순위]`는 한 지표에 속한 네 조각이다. **덩어리 안의 간격은 덩어리끼리의 간격보다 반드시 작아야 한다.** 이걸 어기면 눈은 "라벨"과 "그 옆 덩어리의 값"을 묶어 읽는다.

### 무엇이 잘못됐었나

`.mrow`의 라벨 열이 `minmax(0,1fr)`이라 남는 폭을 **전부** 삼켰다. 실측:

| | 라벨 글자폭 | 라벨→값 간격 |
|---|---|---|
| 광고비 | 30px | **178px** |
| 실유저 | 30px | **208px** |
| 앱 접속(홈피드) 7일 | 93px | **114px** |

한 덩어리여야 할 것들이 가장 멀리 떨어져 있었고, 남는 폭이 행마다 달라 **간격 자체가 114~208px로 들쭉날쭉**했다. 눈이 기댈 규칙이 없었다.

### 규칙

1. **남는 폭은 덩어리 밖으로 흘린다.** 트랙을 `max-content`로 잡고 `justify-content:start`. 덩어리를 늘려 여백을 채우면 관계가 끊긴다.
2. **값·등급·순위 열은 `auto`(내용 폭).** 고정 폭 + 오른쪽 정렬로 두면 짧은 값이 열 왼쪽에 빈틈을 남긴다 — `"5,851"`을 `"4733.7만원"`용 76px 열에 넣으면 48px이 빈다. 홀이 사라지는 게 아니라 자리만 옮긴다.
3. **라벨만 폭을 맞춰 오른쪽 정렬.** 짧든 길든 값 바로 8px 앞에서 끝나고, 라벨 오른쪽 끝·값 왼쪽 끝 두 개의 정렬선이 생겨 행끼리도 이어진다.
4. **그 폭은 고정값이 아니라 블록의 실제 라벨에서 잰다** (`fitMrows()`). 고정 98px로 두면 라벨이 모두 짧은 블록(광고비·실유저 = 30px)에서 열 왼쪽 68px이 그냥 빈다.
5. **열 폭은 실측 최대치로.** 값 `4733.7만원` 74px · 배지 `매우 좋음` 54px · 순위 `상위 100%` 52px. 좁게 잡으면 `nowrap` 텍스트가 열 밖으로 넘쳐 간격을 먹고 옆 조각과 붙는다.
6. **기준 시점(`.uc-when`)은 제목 옆에 붙인다.** `margin-left:auto`로 오른쪽 끝에 밀면 카드에서 240px, 유효 복귀 헤더에서는 **1036px** 떨어져 "무엇의 시점인지" 연결이 끊긴다.
7. 덩어리가 내용 폭까지 줄면 넓은 창에 **3열**이 들어간다. 3→2→1 단계형 중단점(@1360/@1080).

### 불변식과 검증

> **덩어리 내부 최대 간격 < 덩어리 사이 최소 간격**

검증(2026-08-06, 4개 매체 × 상위 8개 소재 × 폭 1560/1360/1100 = 258행):

| | 값 |
|---|---|
| 덩어리 내부 간격 | 8 ~ **25px** |
| 덩어리 사이 간격 | 최소 **40px** |
| 열 겹침 / 열 넘침 | 0 / 0 |

라벨→값 간격은 어떤 라벨·어떤 값이 와도 **8px 고정**(수정 전 114~208px 변동).

> 간격을 잴 땐 **글리프 박스(Range 기준)로 재야 한다.** 요소 박스로 재면 오른쪽 정렬된 텍스트의 열 안 빈 공간이 안 잡혀, 실제로는 48px 벌어진 것이 8px로 보고된다.
